Drop-in Cargo fork

Cargo that cleans up after itself

Every git worktree of a project shares one build directory, which stays under a size limit on its own. There is nothing to configure.

Each worktree is a fresh checkout building one binary. Cargo gives every worktree its own target directory and compiles all dependencies again. The fork compiles them once and reuses them, so later worktrees only build the workspace crates.

Projects share dependencies too

What a cleanup looks like

After a build, at most once an hour, Cargo removes what no checkout has used for a week, then the least recently used units until the project fits. It prints one line when it frees something.

$ cargo build
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.89s
     Cleaned 680 stale build units, 10.1GiB freed (build.gc)

What changes

Your projects, Cargo.toml and .cargo/config.toml stay as they are.

  • One build directory per project. Intermediate files go to ~/.cargo/targets/<name>-<hash>/, where the hash comes from the repository's .git directory. Every worktree lands there wherever it is created, reuses compiled dependencies, and only builds its own crates. Binaries still appear in ./target.
  • Fixed directories. ./target and ~/.cargo/targets cannot be moved: --target-dir, CARGO_TARGET_DIR, build.target-dir and build.build-dir are ignored with a warning, so no flag, env var or tool can scatter build output elsewhere.
  • Dependencies shared by every project. Registry and git dependencies build once in ~/.cargo/targets/shared-deps/ and are reused by any project that needs the same version, features and profile, like Go's build cache.
  • A size limit. Each project keeps to twice its largest build of the last day; shared dependencies keep to 50 GiB. Units unused for a day are removed, nothing a running build has locked is removed, and the crates you are working on keep their incremental caches.
  • No duplicate object files on macOS. Debuggers and backtraces read the objects inside each rlib, so the loose copies beside it are removed.
  • Worktrees build at the same time. Fine-grained locking is on, so parallel agents do not queue on one lock. When two builds need the same dependency at once, one compiles it and the other reuses the result.
  • Less debug info in dev builds. Line tables for your crates, none for dependencies. Backtraces keep file and line. A debug setting in your profile still wins.
  • Cranelift on nightly. cargo build compiles your crates with Cranelift and runs the compiler front end on up to 8 threads. Tests and release builds keep LLVM. The installer adds the Cranelift component when you have a nightly toolchain.
Change a default 
# ~/.cargo/config.toml
[build.gc]
max-size = "auto"      # or "15 GiB", "none"
shared-max-size = "50 GiB"
max-unused = "1 day"
frequency = "1 hour"   # or "always", "never"
enabled = true

Set CARGO_SHARED_DEPS=0 to keep dependencies in the project's build directory, CARGO_DEV_CRANELIFT=0 to keep LLVM on nightly, and CARGO_RUSTC_THREADS=1 for a single-threaded front end.
